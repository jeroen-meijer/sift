# Security policy

## Supported versions

Only the latest GitHub release gets security fixes. Older installers may still be downloadable; they are not patched.

## Reporting a vulnerability

Do not open a public GitHub issue, discussion, or pull request for a security problem.

Use [GitHub Private Vulnerability Reporting](https://github.com/jeroen-meijer/sift/security/advisories/new) (Security → Advisories → Report a vulnerability) when that option is enabled on this repository.

Include:

- What the issue is and how to reproduce it
- Affected Sift version or commit, and OS
- Impact (what someone could do with it)
- For dependency CVEs: evidence that Sift reaches the vulnerable code, or a proof of concept. Naming a CVE on a lockfile version is not enough on its own.

I triage reports when I can. There is no response-time promise and no bounty.
