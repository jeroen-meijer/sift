# V1.2 design gaps (app vs Claude Design)

Source of truth: [`Sift.dc.html`](Sift.dc.html) in this folder, byte-identical to the
downloaded design zip. Checked by reading the markup and by rendering the file in a
browser at 1440 × 900. The Nocturne tokens live in
[`_ds/nocturne-.../styles.css`](_ds).

The two side-by-side PNGs in [`references/`](references) are older renders of the same design
project. They show a play button, a time readout, a sort pill and a
"Drag file to DAW" button that the current `.dc.html` no longer has, so where the
two disagree the `.dc.html` wins. The one thing kept from the PNGs is the time
ruler over the waveform: it is useful, it does not fight the `.dc.html` layout, and
it is drawn as an overlay so the L/R lanes still fill the whole well.

`docs/design/V1.1-GAPS.md` covers the previous pass. Everything below is still open
after it.

---

## A. Views the app does not have at all

1. **Settings is a modal card, not a view.** The design gives Settings the whole
   window: a 212px nav column (`#12141f`) with Playback / Library / Analysis /
   Shortcuts, a scrolling body, and a 44px footer (`#181a28`) with
   "Changes apply immediately." and Close. The app renders a single 520px card with
   a stack of native checkboxes.
2. **Tag management is a modal, not a view.** The design gives it a 300px taxonomy
   column with a "New" button and a "Filter taxonomy…" input, and an editor pane
   with name, parent, colour swatches and a live chip preview. The app can only
   create and delete; `rename_tag`, `move_tag` and `set_tag_color` exist in the
   backend and are never called.
3. **Ask-before-index is a full-screen modal.** The design is a 392px toast pinned
   at `right:16px; bottom:44px` with a folder-plus icon, the path, four buttons and
   "You can keep browsing while this waits."
4. **No "remove missing sample" confirmation.** The design has a 452px dialog with
   the file name and path, a broom row counting the other missing samples, and a
   "Remove all missing…" link. The app deletes straight from the context menu.
5. **No empty-results state.** The design draws a magnifying glass, "No samples
   match", and "Remove a filter chip, or widen the BPM range." over the empty list.
6. **No multi-select bar.** The design puts a 30px accent-tinted strip under the
   list: stack icon, "4 samples selected", total size, `⇧ range · ⌘ toggle`, and a
   drag hint on the right.
7. **Missing-file detail pane.** The design replaces the waveform with a centred
   block: plug icon, "Sift can't reach this file", a paragraph naming the volume,
   and Locate… / Re-check path / Remove from library…. The app shows a red banner
   above the header instead.

## B. Settings that exist in the database and have no UI

`ensure_defaults` already seeds these; nothing reads or writes them from the app.

8. `waveform_view`: Stereo L/R vs Summed mono. `WaveformCanvas` takes a `stereo`
   prop that is never passed.
9. `row_waveforms`, `snap`, `sort_column`, `sort_direction`: all four reset on
   every launch.
10. `ignore_list`: rendered as a read-only `<ul>`. The design has a `#101220` box
    with a remove `x` per row and an "Add pattern" row.
11. `hold_hover_hotkey`: the design's "Hold to hover-preview" row with `Unbound`
    and a Record… button. Neither the setting nor the behaviour exists.
12. `clips_dir`: the design's JIT cache row shows the path *and its size*, with
    Change… and Clear cache. `db_stats` returns no size and there is no way to
    move the directory.

## C. Context menu

13. The design menu is 256px, radius 9, `#22242f`, 26px rows with a 14px icon, a
    label, a right-aligned mono shortcut hint, and `#9184d9` / `#100f1a` on hover,
    with four separator rules. The app menu has no icons, no hints, no rules.
14. Missing items: **Add / remove tags…** (`T`), **Set type ▸**, **Set BPM…**,
    **Set key…**. `set_sample_bpm`, `set_sample_key`, `set_sample_type` and
    `set_sample_tags` all exist in the backend and are never called.
15. Item order differs, and the app has an extra **Analyze** entry the design does
    not have (the design has Re-analyze and Custom analysis… only).
16. None of the shortcuts the menu advertises are bound: `⌘O`, `F`, `T`, `⌘R`,
    `⌥⌘C`, `⌘C`.

## D. Library chrome

17. **Omni bar background is wrong.** The app paints it `#12141f` (sidebar); the
    design is `#181a28`, the same fill as the table header. Height should be a
    fixed 52px rather than padding-derived.
18. **BPM / key chip toggles.** The design draws a 16 × 9 track with a 6px knob and
    the words "half / double" and "relative" inside the chip, after a hairline
    divider. The app draws two outlined mini-buttons reading `½×` and `rel`.
19. **Columns button is permanently disabled.** It has hover styling in the design,
    so it is meant to do something.
20. **Sort indicator.** The design marks the sorted column with
    `ph-bold ph-caret-up` at 8px in `#9184d9`, on Name only. The app appends a
    `" ↓"` / `" ↑"` text arrow to every sortable header, and ascending renders as a
    down arrow.
21. **Empty BPM / key cells** render as blank. The design renders `—`.
22. **No play indicator in the row.** The design puts `ph-fill ph-play` at 8px
    `#b5abfc` before the name of the playing row, and draws a playhead plus a
    played-region gradient over that row's waveform.
23. **Sidebar tag rows show the leaf name.** The design shows the full path
    (`Drums/Breaks`, `Drums/Kick/808`), which is what makes the indented list
    readable.
24. **Status bar copy.** The design says "browse and play while this runs" and, on
    first launch, "0 files indexed". The result count is `#9397ab`, brighter than
    the rest of the bar.
25. **First-launch copy** drifted from the design in both the body paragraph and
    the hint line.

## E. Detail pane

26. **Selection is flat.** The design dims everything outside the selection with
    `rgba(13,14,21,.62)`, fills it `rgba(145,132,217,.10)` inside a
    `rgba(181,171,252,.55)` ring, draws two 3 × 26 `#b5abfc` grab handles, and
    floats a pill reading `2 bars · 4.36 s · drag out = clip`. The app draws a flat
    rectangle and no handles.
27. **Drag-to-DAW for a clip is a transport button.** The design has no such
    button: you drag the selection itself out of the window.
28. **Snap grid.** The app only draws grid lines when the sample has a BPM. The
    design also draws accent-coloured bar lines, which the app never draws.
29. **A muted centre line per lane** is drawn that the design does not have.
30. **Snap control is a native `<select>`** and **preview gain is a native
    `<input type="range">`**. The design has a `#232532` pill with a caret and a
    96 × 3 track with an 11px knob.
31. **The gain readout uses a hyphen.** The design uses a real minus sign (`−`).
32. **No "File missing" badge** beside the filename.
33. **Playhead polling** runs a 50ms `setTimeout` loop for the lifetime of the
    library view, whether or not anything is playing or even selected.

## F. Code structure

Not design gaps, but the reason the gaps above are hard to close.

34. `AppShell.tsx` is 1,195 lines and holds the library, Settings, Custom analysis,
    Remove root and Ask-index markup plus roughly thirty pieces of state.
35. `AppShell.css` is 1,462 lines covering every component in the app.
36. There are no shared primitives, so every toggle, dialog and menu is built inline
    at its call site.
37. `TagNode` is declared twice, in `FolderSidebar.tsx` and in `TagManager.tsx`.
38. Every `invoke` call is untyped and its argument shape is repeated inline.
39. `SampleDto` has no `size_bytes`, so the multi-select bar cannot show a total.
40. There is one frontend test (`src/theme/index.test.ts`) and it does not cover a
    component.

## What this pass changed

Every numbered gap above is closed.

**Structure.** `AppShell.tsx` and `AppShell.css` are gone. In their place:

- `src/lib/`: `ipc.ts` (every command, typed, in one place), `format.ts`,
  `tagColors.ts`, `hotkey.ts`, `omni.ts`, `askIndex.ts`, `bpmPresets.ts`,
  `useSettings.ts`.
- `src/ui/`: the primitives the design keeps reusing: `Switch`, `Segmented`,
  `Slider`, `RangeSlider`, `Checkbox`, `PillSelect`, `Dialog`, `Menu`, `Popover`.
- `src/components/`: one component per thing, with `shell.css`, `library.css`,
  `detail.css` and `views.css` beside them, plus `dialogs/` for the six dialogs.
- `src/styles/`: `tokens.css` (the palette, with the surface steps the Sift
  design adds on top of Nocturne) and `base.css`.

`App` now owns only the shell: routing, stats, folders, tags, settings and the
backend event subscriptions. `LibraryView` owns the library's own state.

**Backend.** `SampleDto` gained `size_bytes`; `DbStats` gained `missing` and
`clips_bytes`; the clips directory moved out of `AppPaths` into `AppState` so
`set_clips_dir` can point it somewhere else. `snap_zero_crossings` and
`audio::zero_cross` make the `Z` legend real.

**Drag.** Rendering a JIT clip inside `dragstart` put a decode between the
gesture and the drag, and macOS had dropped the drag session by the time it
finished. The plugin then unwrapped a NULL session and took the process down.
The clip is now written when the selection settles, so `dragstart` only hands
over a path, and `start_drag_files` checks AppKit still has a live mouse event
before calling the plugin at all.

Chrome heights, surface fills, the table grid template, row heights and the
tag-chip shape match the design markup at 1440 × 900.

## Still out of scope

- Matching the design's generated row-waveform SVG path shape sample for sample.
- "Locate…" as a real file picker that repoints an existing row (the button
  re-checks the path; repointing needs an index migration that is not worth it
  yet).
- The design draws no Library section in Settings even though its nav lists one.
  New files, the ignore list and missing samples live there now, which leaves
  Analysis holding the BPM range and the clip cache.
